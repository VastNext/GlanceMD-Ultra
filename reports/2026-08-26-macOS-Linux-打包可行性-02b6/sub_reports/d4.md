## 关键发现

### 推荐实施顺序

#### 阶段 0：先建立跨平台编译骨架

- 把 Windows dependencies/build-dependencies 移到 target-specific sections。
- `build.rs` 仅在 Windows target 编译资源。
- 用 `cfg_attr` 约束 Windows subsystem。
- 把 WebView 构建、resize、stdin pipe 检测和 single-instance 放进平台边界。
- 把自定义协议初始 URL 改为按 target 选择。

验收：Windows 行为不回退；macOS 和 Linux 原生 CI 至少通过 `cargo check`/release build。

#### 阶段 1：macOS MVP

- 先启用系统窗口装饰，避免第一版复制 Windows chrome。
- 支持 Command 快捷键和正确 UI 提示。
- 处理 `Event::Opened`、冷启动缓存与运行中再次打开文档。
- 生成 `.icns`、`.app`、DMG 和文件关联。
- 先发布 unsigned preview 给内部测试；正式版完成 Developer ID 签名、公证、staple。
- 构建 arm64 与 x86_64；优先合成 Universal 2。

验收：Apple Silicon 与 Intel（或 Rosetta 辅助但不能完全替代 Intel 实机）均完成核心操作；`codesign --verify`、`spctl`、`stapler validate` 通过；从隔离下载态首次启动无 Gatekeeper 阻断。

#### 阶段 2：Linux MVP

- 采用 GTK container + `build_gtk` 目标实现 X11/Wayland 双支持；若周期受限，明确首版仅 X11，不能笼统宣称全 Linux 桌面可用。
- 添加 Ubuntu 构建依赖和 runtime dependency 策略。
- 生成 desktop entry、图标、MIME association、`.deb` 与 AppImage。
- 首发只做 x86_64；arm64 后置。

验收：Ubuntu 24.04 GNOME Wayland、至少一个 X11 会话、KDE Wayland 启动与核心功能通过；`.deb` 在干净 VM 自动拉取依赖；AppImage 在定义的发行版矩阵通过。

#### 阶段 3：一致性与维护

- 完成 Unix 单实例与文件转发；若 Wayland 无法强制前置，接受“通知/任务栏提醒”而非硬聚焦。
- 增加平台菜单或保留统一 Web UI 的体验取舍。
- Linux arm64、自动更新、Flatpak/Homebrew/AUR 作为需求驱动的后续项。

### 建议 CI 矩阵

| Job | Runner/target | 主要任务 | 产物/门禁 |
|---|---|---|---|
| Windows x64 | `windows-latest` / `x86_64-pc-windows-msvc` | 现有 release build | EXE，回归 smoke |
| macOS arm64 | `macos-latest` / `aarch64-apple-darwin` | build、基础测试 | arm64 binary |
| macOS Intel | `macos-15-intel` / `x86_64-apple-darwin` | build、基础测试 | x86_64 binary |
| macOS package | macOS runner | `lipo`、app/DMG、签名、公证 | Universal 2 DMG |
| Linux x64 | Ubuntu 24.04 或所选最低基线 / `x86_64-unknown-linux-gnu` | 安装 GTK/WebKitGTK dev 包、build/package | deb、AppImage |
| Linux smoke | VM/容器 + Xvfb，外加实机 Wayland | 启动与功能测试 | 日志、截图/人工清单 |

### 核心功能验收清单

- 启动、退出、最小化/最大化、窗口状态恢复。
- 打开、另存为、保存 UTF-8 文件及含空格/中文路径。
- CLI 打开文件；Finder/文件管理器双击；运行中再次打开第二个文件。
- 多文件拖放、单实例策略（若启用）、窗口聚焦/通知。
- 编辑/预览/分屏、图片本地协议、最近文件路径。
- 全部快捷键、缩放、触控板/滚轮、IME（中日韩输入法）。
- 深浅主题、字体回退、高 DPI、多显示器。
- 断网启动（所有前端资源内嵌）、无开发工具暴露。

## 分析

最安全的路线不是同时追求所有格式和完全一致体验，而是先把“平台差异隔离”做成稳定骨架，再按 macOS、Linux 顺序逐个平台闭环。macOS 的系统 WebKit 和统一硬件/OS 环境使其更适合作为第一个新增平台；Linux 的发行版、桌面环境、WebKitGTK 动态依赖和 Wayland 组合更需要兼容矩阵。

如果目标只是让开发者能运行，工作量可压缩到条件编译 + 原生 binary；如果目标是普通用户下载即用，打包、桌面关联、签名、公证和真实机器测试与代码适配同等重要。

## 对终稿的贡献

提供最小可行范围、阶段依赖、CI/测试矩阵、工作量等级和风险回退方案。

## 不确定性与空白

- 工作量只按工程范围分级，未基于团队速度给出天数。
- GitHub Actions 无法完全替代 macOS/Linux GUI 实机验收；尤其是 Wayland、IME、拖放和 Gatekeeper 隔离态。
- 若要求 Mac App Store、Flatpak/Flathub 或发行版官方仓库，需增加各渠道单独的 sandbox/审核/manifest 工作，不在当前范围。
