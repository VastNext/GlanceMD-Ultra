## 关键发现

### 工具链

- 官方 `fnpack 1.2.3` 可在 Windows x86、Linux x86/ARM、macOS Intel/Apple Silicon 上运行。
- 创建普通应用：`fnpack create <appname>`；Docker：`fnpack create <appname> --template docker`；打包：`fnpack build`。
- `fnpack` 在生成 `.fpk` 前检查 Manifest、权限/资源 JSON、双尺寸图标、app/cmd/wizard 和 UI 路径。
- 真机可通过应用中心手动安装，或用 `appcenter-cli install-fpk`/`install-local` 自动化调试。

### 推荐 FPK 结构

```text
glancemd/
├── manifest
├── ICON.PNG
├── ICON_256.PNG
├── app/
│   ├── server/          # 后端与静态前端
│   └── ui/
│       ├── config
│       └── images/
├── cmd/
│   ├── main
│   ├── install_init / install_callback
│   ├── upgrade_init / upgrade_callback
│   └── uninstall_init / uninstall_callback
├── config/
│   ├── privilege
│   └── resource
└── wizard/
```

安装后 `app/` 进入 `target`，配置、数据、临时文件分别使用系统创建的 `etc/var/tmp/home`，不得硬编码卷号，应使用 `TRIM_APPDEST`、`TRIM_PKGVAR` 等变量。

### Manifest 和权限

- `source=thirdparty`；首版若只包含 JavaScript/Node 代码并依赖官方 Node runtime，可用 `platform=all`。若打入 Rust 二进制，必须分别提供 x86/ARM 包或只声明真实架构。
- 使用统一网关时可不开放固定端口；`desktop_uidir=ui`，入口配置实际位于 `app/ui/config`。
- 需要 JS SDK 时必须 `micro_app=true`。
- Markdown 编辑器必须允许授权目录，不能设置 `disable_authorization_path=true`。
- 长期服务应使用 `run-as=package` 专用用户；文件 ACL 通过用户授权和 API 管理，不应以 root 绕过。

### 文件能力声明

`config/resource` 应只声明实际 Scope，例如：

```json
{
  "api-scope": [
    "trim.file.userAccess",
    "trim.file.userAcl",
    "trim.file.path"
  ]
}
```

前端用 `@trimjs/web-app` 打开用户文件/目录授权；后端通过系统 Unix Socket API 查询授权、检查当前 UID 对目标路径的读写权限。Token 来自 `TRIM_API_TOKEN`，不得持久化或发送到前端。

### 生命周期

- `cmd/main start/stop/status` 必须幂等；status 运行中返回 0，未运行返回 3。
- 日志、PID、Socket 应放在 `TRIM_PKGVAR`/`TRIM_APPDEST` 的合适位置。
- 用户可见失败写入 `TRIM_TEMP_LOGFILE`。
- 更新流程需要处理配置和持久数据兼容，卸载应尊重用户是否保留数据。

## 分析

FPK 不是把 `.deb` 或 AppImage 再压缩一层。它是飞牛应用中心的声明式生命周期包，负责身份、权限、用户入口、资源和安装更新。GlanceMD 需要新增独立的 `packaging/fnos/`（或类似）层，而不是把现有 Linux 产物塞进包里。

官方 Native Notepad 案例几乎就是目标模板：编辑器 Web UI、Node 后端、每用户身份、数据读写、Unix Socket 网关。差别在于 GlanceMD 编辑的是用户授权目录中的现有 Markdown 文件，而不是应用私有笔记文件，因此权限检查和路径规范化要求更严格。

## 不确定性与空白

- 官方文档虽公开，但不同 fnOS 版本对开放 API 的最低版本不同；文件 ACL 文档明确要求系统 1.2.0401、App 1.34.0，最终 `os_min_version` 需按所有采用 API 的最高要求设置。
- 目前未在真机验证 `fileTypes` 的 path 参数与新授权 API组合的完整行为。
