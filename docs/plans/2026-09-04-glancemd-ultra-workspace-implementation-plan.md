## 0. 计划前提

### 0.1 独立仓库决策

调研建议"同仓共享核心、双产品入口"，维护者已于 2026-09-04 决定独立建仓（见 `docs/adr/0001-glancemd-ultra-独立仓库.md`）。对本计划的影响：

- 本仓库唯一产品即 GlanceMD Ultra，不做双产品 feature gate。
- 与 `VastNext/GlanceMD` 共同拥有的编辑内核缺陷修复需双向 cherry-pick（提交信息加 `[sync]` 标注）。
- 轻量目标表述为 Ultra 自身约束：二进制 2–8 MB 以内（2026-09-09 放宽，见决策变更记录），不采用 Electron/Monaco。

### 0.2 不可重新打开的决策事项

以下为 `naming-and-planning-readiness.md` §5 固化的决策，本计划不得调整，仅当用户明确改变产品决策时才可重开：

- 一个窗口一个项目；打开另一项目询问新窗口或替换。
- 项目树与 Outline 同时显示，默认并排，可设置 Outline 在右。
- 第一版支持 Ctrl/Shift 多选，多选时 reveal 禁用。
- 文件监听、自动重载、dirty 冲突保护为必需能力。
- 新建、重命名、回收站删除、永久删除、复制、移动、撤销为必需能力。
- 全文搜索、Ctrl+P、设置、快捷键和命令面板为必需能力。
- Delete 进回收站，Shift+Delete 永久删除并二次确认。
- 第一阶段仅 UTF-8/BOM、保留换行；GBK 等编码后置。
- 二进制允许 2–8 MB，但保持原生轻量。

### 0.3 工程约定（继承自 AGENTS.md）

- 分支 `feat/<主题>` / `fix/<主题>` / `chore/<主题>`；Conventional Commits，中文描述。
- 合入 main 门禁：`cargo test`、`cargo fmt --check`、Playwright 冒烟套件全绿（自阶段 0 建立后）、四平台 CI Build 全绿；UI 改动需明暗双主题截图验证。
- 打 tag 即发布（`release.yml`）；tag 必须与 `Cargo.toml` 版本一致。
- JS 继续 IIFE 模块化；不引入前端构建链与 npm 依赖。
- Rust 体积配置保持 `opt-level = "s"`、`lto = "fat"`、`panic = "abort"`、永不 strip 符号。

### 0.4 版本序列

Ultra 采用独立 semver 序列：阶段 0–6 期间为 `0.x.0` 内部版本（tag 触发 Release 供内部验证），首个对外稳定版为 `v1.0.0`。

### 0.5 平台优先级

开发与日常验证以 **Windows 为主平台**：各阶段的功能开发、冲突矩阵与性能门禁先在 Windows 全量执行并作为进入下一阶段的门禁；macOS/Linux 的完整功能矩阵按 §4 风险表节奏在阶段 3 与阶段 7 两次执行，`v1.0.0` 发布前三平台矩阵必须全绿。各阶段交付的 Rust 层单元测试与前端冒烟套件本身跨平台可运行，用于提前暴露平台差异。

## 1. 目标架构（来自方案 §9，落地为本仓库目录）

```text
src/
├── main.rs                  窗口、事件循环、CLI
├── ipc.rs                   现有 IPC 通道 + 新增 workspace 通道
├── file_codec.rs            [新] UTF-8/BOM/换行元数据读写
├── atomic_save.rs           [新] 原子保存
├── workspace/               [新] Workspace 子系统
│   ├── mod.rs               生命周期、可信项目根
│   ├── tree.rs              懒加载目录树、过滤、符号链接策略
│   ├── operations.rs        新建/重命名/移动/复制/删除/撤销
│   ├── watcher.rs           监听、去抖、合并、自身事件抑制
│   ├── search.rs            后台搜索、取消、增量结果
│   ├── recovery.rs          崩溃恢复与会话恢复
│   └── settings.rs          设置 schema、合并、迁移
├── platform/                [新] 平台能力抽象
│   ├── reveal.rs            Explorer / Finder / xdg-open
│   ├── trash.rs             回收站 / 废纸篓
│   └── terminal.rs          在终端打开
└── frontend/
    ├── workspace.js         [新] Workspace 会话与跨模块事件协调
    ├── project-tree.js      [新] 树、懒加载、多选、拖放、菜单
    ├── outline.js           [拆] 从 app.js 拆出 Outline
    ├── search-panel.js      [新] 全文搜索 UI
    ├── quick-open.js        [新] Ctrl+P
    ├── settings.js          [新] 设置 tab
    ├── keybindings.js       [新] 命令注册与快捷键
    ├── command-palette.js   [新] Ctrl+Shift+P
    ├── recovery.js          [新] 冲突横幅、删除与崩溃恢复 UI
    └── tabs.js              保持文档 tab 单一职责
```

事件模型：Rust 是文件系统唯一可信方，通过结构化事件（`workspace:opened`、`workspace:file-changed`、`workspace:search-result` 等，全集见方案 §9.3）经 IPC 桥广播；前端 `workspace.js` 统一分发给树、tab、Outline、搜索、恢复模块。禁止任何模块自行猜测磁盘状态。

候选依赖（阶段 0 spike 后锁定，均为成熟低依赖 crate）：`notify`（监听）、`trash`（回收站）、`ignore` 或 `walkdir`（目录枚举与 glob 排除）。锁定前以 10k 文件实测为准（见 §2 阶段 1 门禁）。

## 2. 阶段计划

每个阶段 = 独立分支 + 独立验收标准 + 回归清单 + 可发布的垂直切片。估算为单人串行。

### 回归自动化策略（贯穿各阶段）

前端保持零依赖原则，测试基建同样不引入前端构建链与 npm 运行时依赖（Playwright 仅作为开发/CI 工具，不进产物）：

- **分层**：
  1. Rust 层：`cargo test` 单元/集成测试，承载文件操作、监听去抖、设置迁移、编码往返等逻辑主体的验证。
  2. 前端冒烟：Playwright 驱动组装测试页（与 `main.rs::build_html` 相同的占位符拼接 + `window.ipc` mock）。用例随阶段累积——阶段 N 结束时，冒烟套件必须覆盖阶段 0–N 全部核心路径（打开/保存/tab/树/搜索/设置等）。
  3. 人工专项：仅保留无法自动化的系统交互——明暗双主题视觉截图、原生对话框、回收站"还原"、资源管理器/Finder reveal、终端打开、真实 kill -9 恢复。
- **节奏**：以下各阶段的"回归清单"自阶段 1 起按此执行——先跑累积冒烟套件，再执行本阶段人工专项；不再逐阶段人工重跑全部历史场景。
- **CI 接入**：冒烟套件自阶段 1 起并入 `build.yml`（至少 Windows runner 执行，避免四平台矩阵成倍拉长耗时）；视觉截图对比仍以本地人工验证为准。

### 阶段 0：仓库身份与架构地基（1–2 周；UI 设计基线可延展至阶段 1 前期并行收尾）

**交付内容**

1. 身份重命名（一次性原子提交，涉及 CI 与发布，不与其他改动混合）：
   - Cargo package → `glancemd-ultra`；Windows 产物 → `GlanceMD-Ultra.exe`；配置目录 → `glancemd-ultra`
   - localStorage 前缀 → `glancemd-ultra-`；Bundle ID → `com.vastnext.glancemd-ultra`
   - `build.yml` / `release.yml` 产物命名与校验逻辑同步更新
   - README / README.en 改写为 Ultra 定位（"面向本地 Markdown 与结构化文本项目的轻量原生工作区编辑器"）；AGENTS.md 已完成 Ultra 化更新、CLAUDE.md 已废弃删除（见决策变更记录）
   - 版本号设为 `0.1.0`，打 tag `v0.1.0` 验证发布链路
2. 命令注册表：Rust 与 JS 各建单一命令表，命令 ID 唯一；菜单、按钮、快捷键只引用命令 ID。将至少一个既有菜单动作（如"打开文件"）迁移到注册表以验证模式。
3. Workspace IPC 通道与事件桥骨架：定义事件枚举与序列化格式，打通 Rust → JS 广播与 JS → Rust 命令两条链路。
4. 可信项目根：`workspace::mod` 提供项目根规范化与路径边界校验工具函数（后续所有文件操作强制经过）。
5. `platform/` 模块 trait 定义 + 三平台空实现（编译通过即可，行为在阶段 3 填充）。
6. 清理仓库遗留：README 截图、screenshot 文案中与旧品牌相关的部分随身份重命名一并处理；`docs/PLAN.md` 已归档至 `docs/archive/PLAN.md`，`reports/` 与 `docs/` 其余部分保留作为决策与研究档案。
7. 测试与设计基建：
   - Playwright 冒烟框架：组装测试页 + `window.ipc` mock + 首批用例（新建/打开/保存/tab 切换/主题切换/拖放），覆盖既有单文件功能核心路径。
   - UI 设计基线：延续既有紫粉渐变设计语言，产出项目树/Outline/欢迎页/冲突横幅/搜索面板/设置页的静态 HTML 设计稿（明暗双主题），存入 `docs/design/`，作为后续阶段 UI 实现与截图验收的对照基准。

**垂直切片**：CLI 传入目录 → Rust 打开 Workspace → 前端收到 `workspace:opened` 与 `workspace:scan-progress` 事件（UI 上先以状态栏文字呈现，无树 UI）。

**验收标准**

- `cargo build --release` 产物为 `GlanceMD-Ultra.exe`，体积 ≤ 5 MB。
- 四平台 CI 绿；`v0.1.0` tag 触发 `release.yml` 产出五件套（产物名已更新）。
- 命令注册表迁移后的菜单动作行为与迁移前一致。
- 既有单文件功能（打开/保存/tab/主题/拖放）回归通过，且已沉淀为 Playwright 冒烟首批用例并本地全绿。
- UI 设计基线稿经维护者确认并入库 `docs/design/`。

**回归清单**：`cargo test` 全量；手动：新建/打开/保存/tab 切换/暗色主题/拖放文件到窗口。

### 阶段 1：项目浏览（2–3 周）

**交付内容**

- 打开目录：对话框 + CLI 参数 + 拖放目录；一窗口一项目；打开另一项目时询问"新窗口 / 替换当前"。
- 懒加载目录树（`tree.rs`）：默认展开第一层；默认可见扩展名（`.md .markdown .txt .json .yaml .yml .toml .ini .csv`）；默认排除 `.git node_modules target .venv dist build .cache`；默认隐藏隐藏文件；显示文件符号链接、不递归目录符号链接。
- 会话恢复：上次项目、tab、活动文件、光标/滚动位置、树展开状态、面板宽度/折叠状态。
- 欢迎页与菜单的最近项目列表，支持固定与移除失效记录。
- 多选：Ctrl/Shift 多选（本阶段先做选中状态与视觉，批量操作在阶段 3 接入）。
- 双布局：默认项目树+Outline 两个竖栏并排；设置可切 Outline 在右；两面板可折叠、拖宽、持久化；1024px 宽度下有最小宽度约束仍可操作。
- "定位当前文件"按钮：展开祖先、选中并滚动；切换 tab 只同步高亮不滚动。
- Ctrl+P 快速打开：索引来自 Workspace 文件清单，不重复扫盘。
- 完整键盘操作：方向键、Enter、F2（重命名 UI 本阶段可占位为禁用态）、Delete（本阶段可占位）、菜单键。

**垂直切片**：打开真实 10k 文件项目目录 → 树懒加载展开流畅、Ctrl+P 秒级命中、恢复会话后回到上次现场。

**验收标准**

- 10,000 文件目录：首次扫描与展开不阻塞 UI（主线程无 >100ms 卡顿）；此为门禁——通过后才锁定 `notify`/`ignore` 技术选型并允许进入阶段 2/4。
- 双布局切换、折叠、拖宽、持久化均生效；与既有 split 预览共存。
- 单击文件永久打开 tab（无预览 tab）；文件在项目内复用当前工作区。
- 明暗双主题下树、多选、定位高亮截图验证。

**回归清单**：阶段 0 全部 + 单文件打开（项目外文件仍可作为独立文件打开）。

### 阶段 2：监听与冲突（1.5–2.5 周）

**交付内容**（`watcher.rs` + `recovery.js` 冲突部分）

- `notify` 接入 + `files.watcherExclude` 默认排除生效。
- 事件去抖、合并；应用自身保存与文件操作事件抑制（回环抑制）。
- Clean tab 外部修改 → 自动重载，保留光标/滚动，状态栏短暂提示。
- Dirty tab 外部修改 → 顶部非模态冲突横幅：重新加载 / 保留编辑版本 / 另存为；"保留编辑版本"后再保存必须二次确认覆盖。
- 外部删除：保留内存内容，提示"磁盘文件已删除"，提供另存为/关闭。
- 外部移动：可唯一识别时更新路径，否则按删除+新增处理。
- `workspace:watcher-error` 事件与 UI 提示。
- "暂停文件监听"命令（如排期紧张可移至阶段 5 随命令面板交付）。

**验收标准**：冲突矩阵全绿——{clean, dirty} × {外部修改, 外部删除, 外部移动, 自身保存}。矩阵先在主开发平台 Windows 全量执行并作为进入阶段 3 的门禁，macOS/Linux 两列按 §0.5 节奏在阶段 3 与阶段 7 复跑补齐；任何组合下不出现静默数据丢失；去抖单元测试覆盖事件风暴场景（1s 内 100 次同文件写入只触发一次重载）。

**回归清单**：阶段 1 全部；重点回归自身保存不触发自动重载循环。

### 阶段 3：文件操作（2–3 周）

**交付内容**（`operations.rs` + `platform/` + `project-tree.js` 右键菜单）

- 新建文件（无扩展名自动补 `.md`）/ 新建文件夹；重名阻止并提示。
- 内联重命名（F2 / 右键 / 双击节点名）。
- Delete → `trash` crate 进回收站/废纸篓；Shift+Delete → 永久删除 + 二次确认；删除已打开且有未保存内容的文件先阻止并提示。
- 剪切/复制/粘贴；拖放移动、Ctrl+拖放复制；跨磁盘移动 = 复制后删除 + 失败回滚。
- 复制绝对/相对路径；在系统文件管理器中显示（多选时禁用；Linux 允许降级为打开父目录）；在终端中打开；手动刷新。
- 撤销栈：重命名、移动、可恢复的回收站删除支持 Ctrl+Z；永久删除不可撤销。
- 多选批量：复制、移动、回收站删除、永久删除。
- **Workspace 事务**：任何文件操作同步更新——项目树路径、受影响 tab（路径/标题/保存目标）、最近文件、活动文件高亮、监听映射、搜索结果、恢复状态、窗口标题。
- 禁止越出项目根（路径边界校验强制）。

**验收标准**：每个操作在 Rust 层有单元测试（含越界拒绝、重名拒绝、跨盘移动回滚）；回收站语义在 Windows 资源管理器中可"还原"；文件操作事务的端到端测试覆盖"移动目录后打开中的 tab 保存目标正确"。

**回归清单**：阶段 1–2 全部；重点回归删除后树/tab/搜索状态一致。

### 阶段 4：搜索（1.5–2 周，可与阶段 3 并行）

**交付内容**（`search.rs` + `search-panel.js`）

- 后台线程执行、可取消、增量返回；搜索 Markdown 与受支持文本文件。
- 选项：大小写敏感、全词、正则、包含/排除 glob（`search.exclude` 生效）。
- 跳过二进制与超大文件（>5 MB 或阈值可配置）；结果数上限。
- 点击结果：打开/切换 tab、跳到行列并选中匹配；split 下编辑器与预览同步定位。
- 不做全项目替换（明确非目标）。

**验收标准**：10k 文件目录全文搜索出首结果 < 1s、全量完成 < 5s（中端硬件基准，实际门禁值在 10k 实测后校准记录）；取消后线程在 500ms 内退出；正则非法输入不崩溃并提示。

**回归清单**：搜索结果打开的文件若已被外部删除（阶段 2 场景），不得崩溃。

### 阶段 5：设置与快捷键（2–3 周；执行中）

**当前状态（2026-09-06，v0.1.0，Wave 2a）**：设置 schema v1、七类设置 UI、设置搜索、全局/项目覆盖、项目树与 Outline 侧栏布局、快捷键编辑器、语言/主题接线及设置 v2 视觉基线已落地。工作区当前可打开项目目录并使用项目树进行文件浏览与基础文件操作（新建、重命名、移动、复制、删除、撤销、系统文件管理器 reveal、终端打开），并提供 Outline、项目级搜索、文件监听/冲突提示及基础恢复 UI。此处仅记录 v0.1.0 当前实现，不代表本计划完成；完整监听/恢复、跨平台矩阵、全工作区事务和发布门禁仍未完成。

当前快捷键仅为**基础快捷键/有限自定义**：可对现有单段快捷键进行录制、冲突提示、清除、恢复默认和持久化。v0.1.0 明确不含 chord、context、多键位方案（multi-scheme）、Key Assist 或 Vim。`docs/design/prototypes/settings-sidebar-v2.html` 仅作为视觉/交互基线，schema 七类保持不变；custom select、密度公式、动态宽度与 420px 编辑器下限的批准规则记录于 `docs/dev/contracts/settings.md` §8。独立 overlay 与产品 custom select DOM 尚未接入，不在本轮测试中假造接口。

**强快捷键方向（仅评估，全部尚未实施）**：用户最终确认采用 Eclipse 式架构与导航语义，首装默认启用 Eclipse scheme，同时提供完整 VS Code scheme；所有公开命令都必须有默认键。Eclipse 键位包括 `Ctrl+O` Quick Outline、`Ctrl+Shift+S` Save All、`Ctrl+E` Quick Switch、`Ctrl+H` Search、`Ctrl+3` Find Actions。Ultra 扩展包括 `Alt+Shift+F O` 打开文件、`Alt+Shift+F P` 打开项目、`Alt+Shift+S` 另存为、`Alt+Shift+P` 打开设置、设置内 `Alt+Shift+P K` 进入快捷键页、`Alt+Shift+E V` 切换 Vim。Vim 属于编辑器层，首版目标为常用完整集。该方向的完整测试门禁预计 **398–588 项**；上述强快捷键系统、scheme、chord、context、Key Assist、Vim 及对应测试目前全部尚未实施。

**交付内容**（`settings.rs` + `settings.js` + `keybindings.js` + `command-palette.js`）

- 设置 schema v1（带版本字段与迁移框架）；全局 + 项目设置（`.glancemd/settings.json`），项目覆盖全局；是否自动创建项目设置文件由全局设置控制。
- 设置 tab：左分类右设置项 + 搜索；分类覆盖方案 §7.1 全部七类；"打开设置 JSON"入口。
- 既有散落的持久化项（主题、布局、窗口状态）迁入统一设置体系并完成迁移测试。
- 快捷键页：命令搜索、组合键录制、冲突检测（冲突阻止保存）、清除、恢复默认、导入/导出。
- 平台键位显示：Windows/Linux 用 Ctrl/Alt，macOS 用 Cmd/Option。
- Ctrl+Shift+P 命令面板：所有命令可搜索执行（依赖阶段 0 注册表全覆盖）。

**验收标准**：schema 版本迁移有单元测试；快捷键冲突用例（如把 Ctrl+S 录制到另一命令）被阻止保存；命令面板能执行所有已注册命令；项目设置覆盖全局的优先级测试。

**回归清单**：老版本配置升级路径；快捷键恢复默认后与出厂一致。

### 阶段 6：数据保护（1.5–2.5 周）

**交付内容**（`file_codec.rs` + `atomic_save.rs` + `recovery.rs` + `recovery.js`）

- 原子保存：临时文件写入 → 替换目标；与阶段 2 回环抑制联动。
- 编码：UTF-8 与 UTF-8 BOM 读写；保留原 LF/CRLF；非 UTF-8 明确提示不支持（不静默错误解码）。
- 自动保存：默认关闭；可选延时 / 失焦模式。
- 崩溃恢复：编辑中未保存内容周期性写入恢复区；异常退出后下次启动提示恢复（逐文件选择）。
- 退出/切换项目时 dirty 文件列表：全部保存 / 逐个处理 / 全部放弃 / 取消。
- 大文件模式：>5 MB（可配置）禁用实时预览、Outline 与高耗时功能。

**验收标准**：强制 kill -9 后重启可恢复未保存内容；原子保存在模拟中断（写入过程杀进程）后目标文件不损坏；BOM 与换行符往返（读→存→读）零漂移测试。

**回归清单**：阶段 2 冲突矩阵重跑（原子保存改变写入路径，必须重验回环抑制）。

### 阶段 7：稳定与发布（2–3 周）

**交付内容**

- 10k 文件全链路性能复测（扫描/树操作/搜索/监听同时活动）。
- 三平台手工验证矩阵执行并归档（冲突矩阵、文件操作、回收站、reveal/终端、快捷键）。
- 文档定稿：README（双语言）、AGENTS.md（Ultra 工作流）、用户文档；`docs/` 与 `reports/` 历史档案归位。
- 发布链路：`v1.0.0-rc.1` → 修复 → `v1.0.0`；Release Notes 按 AGENTS.md 规范撰写（中文、分节、macOS 未签名提示）。

**验收标准**：成功标准全集（方案 §11）逐项核对通过；`v1.0.0` 五件套产物齐全且体积 ≤ 8 MB；GlanceMD 仓库未受本仓库影响（不要求其同步任何改动）。
