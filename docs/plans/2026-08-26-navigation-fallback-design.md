# 意外导航保护与回退提示设计

## 目标

当预览中的链接未被正常处理时，GlanceMD 仍需保留标题栏、标签页、工具栏和窗口控制，不能让主 WebView 导航到 404 白屏。

## 方案

- 在前端捕获预览链接：本地文件继续交给 `open_file` IPC，页内锚点保持默认行为，网络链接保持现状。
- 在 WebView 宿主层拦截离开应用根页面的主框架导航，作为前端处理遗漏时的最后防线。
- 导航被拦截后，通过现有 Rust → JavaScript 事件通道通知前端，在预览内容上方显示非破坏性的错误提示。
- 错误提示提供“返回文档”“重试”和关闭按钮；返回和关闭仅移除提示，重试重新按本地文件规则处理目标地址。

## 交互与视觉

- 提示使用现有 Catppuccin 深浅主题变量、圆角与按钮风格。
- 不清空当前预览，不改变活动标签，不新增页面级路由。
- 键盘焦点进入提示；按钮具有可见焦点样式和中文无障碍标签。

## 验证

- 自动化测试覆盖导航判定、错误事件、返回、重试和关闭。
- Windows Release 构建成功。
- 使用真实 WebView 打开 `D:\Software\CLIProxyAPI\README.md`，验证正常点击中文可打开文件；模拟漏网导航时应用壳保留且回退按钮可用。
