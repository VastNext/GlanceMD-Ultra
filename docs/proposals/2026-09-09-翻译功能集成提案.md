## 1. 背景

GlanceMD Ultra 用户（尤其读写双语文档的技术写作者）需要在编辑器内对选中文本快速翻译。VastTranslator 浏览器插件已沉淀成熟的翻译引擎层（Google / Bing / 自定义 OpenAI 兼容 API + 分段对齐协议），本提案规划将其核心能力集成进 GlanceMD Ultra。

## 2. 可行性结论（v0.5.2 基线复核）

**可行，且实施条件比初版评估更成熟。** 三个关键前提在 v0.4.0–v0.5.2 期间已全部落地：

| 前提 | 现状 | 对本功能的价值 |
|---|---|---|
| HTTP 通道 | `src/net.rs::build_agent(proxy_uri, strict_ssl, timeout)`（FEAT-003，v0.4.0） | 带代理/TLS 的 ureq Agent 直接复用，`ureq` 依赖已就位，**零新增网络依赖** |
| 异步 IPC 模式 | `net.testProxy`：`std::thread::spawn` + `Event` 回执 + 前端 `Workspace.on`（commands.rs:1651、events.rs、settings.js:1400） | 翻译请求照搬此模式，不阻塞 UI |
| 诊断日志 | `src/logger.rs`（v0.5.2） | 网络失败排障直接用 `log_info!`/`log_warn!` |

插件侧可移植资产（约 1000 行纯 TS，无 Chrome API 依赖）：

- **三引擎客户端**：`google-translate-client.ts`（40 行）、`bing-translate-client.ts`（34 行）、`openai-client.ts`（224 行，含 response_format 400 降级重发）
- **基础设施**：`translate-http.ts`（30s 超时 + 429/Retry-After）、`retry.ts`（指数退避 500ms×2^n 封顶 30s）、`batching.ts`（8 段/6000 字符分批 + 按 id 重排）、`messages.ts`（结构化提示词 + **id 对齐校验**，防 AI 漏翻错位）
- **语言表**：`languages.ts`（12 语言 + Google/Bing 语言码映射 + 归一化）
- **不移植**：DOM 扫描/注入渲染层、`chrome.*` 消息路由、React popup/options

GlanceMD 侧承接条件（复核新增发现）：

- 编辑器为纯 `<textarea>`，选区 `selectionStart/End` 直取
- **`caret.js`（CustomCaret）已解决 textarea 内光标像素定位**（含 softwrap/滚动/缩放跟随）——划词气泡的定位难题已有现成测量方案可借用
- 设置体系统一在 **Rust schema**（settings.rs + settings.js 声明式字段 + settings-apply），新持久化项必须走该体系（见 §6 决策修正 1）
- `ipc.rs::registry_command_id` 通配前缀清单需补 `translate.`（BUG-001 同款教训，测试锁死）

## 3. 架构方案

```
textarea 选区（translate.js 监听 mouseup/selectionchange）
  → 浮动翻译按钮 → 点击（或 Alt+T 命令）
  → 组装请求 {requestId, segments:[{id,text}], source, target}
  → window.ipc.postMessage("translate.request")
  → Rust commands::translate_request
      ├─ 读取全局设置 http.*（代理）与 translation.*（引擎）
      ├─ net::build_agent(...) 构造 Agent
      └─ std::thread::spawn：
           translate.rs 按引擎分发 → 分批 → 逐批请求（带重试）→ 按 id 重排校验
  → emit Event::TranslateResult {requestId, ok, results|message}
  → 前端 Workspace.on("workspace:translate-result") 按 requestId 关联
  → 气泡展示译文 → 替换选区 / 插入到选区后 / 复制
```

要点：

1. **引擎逻辑全部在 Rust**（`translate.rs`，自包含风格对齐 `net.rs`，可 `#[path]` 独立编译测试）：CORS 天然不存在，apiKey 不经过前端 JS 上下文，代理统一生效。
2. **前端只做交互**：选区监听、气泡状态机（loading/result/error/retry）、requestId 关联（过期回执静默丢弃）。
3. **v1 无取消**：跨 IPC AbortController 不做，30s 超时兜底（与插件 `translate-http.ts` 一致）；过期结果丢弃即可，无副作用。

## 6. 相对初版提案的决策修正

1. **配置存储改道**：初版写 localStorage——**修正为统一设置体系**（Rust schema `translation` 分类）。依据：计划 §阶段 5 明确"散落持久化项迁入统一设置体系"；附带收益是 apiKey 经 Rust 持久化，不暴露在前端 localStorage。
2. **触发交互简化**：不做插件的 modifier×连击触发器（浏览器多页面场景防误触的产物）；编辑器场景用「选中浮现按钮 + `Alt+T` 命令」双路径即可。
3. **v1 明确不做**：SSE 流式、选区上下文消歧、专家提示词、翻译缓存、请求取消（超时兜底）——全部列为后续增强另行立项。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| Google/Bing 公开接口限频（429）或风控变化 | 移植指数退避重试；错误文案明示状态码；自定义 AI 引擎兜底 |
| 国内网络不可达 Google | FEAT-003 代理已就绪，`net::build_agent` 统一加载 `http.*` 设置；设置页测试连接先验证链路 |
| OpenAI 兼容端点行为差异（response_format 不支持等） | 沿用插件 400 降级重发策略；id 对齐校验失败即报错不静默 |
| textarea 选区像素定位偏差（softwrap） | 借用 CustomCaret 既有测量实现；e2e + 双主题视觉验证兜底 |
| apiKey 明文落盘 | 与既有设置体系一致，文档声明；后续可评估系统凭据库（另立项） |

## 8. 验收标准

1. 选中编辑器文本浮现翻译按钮（可设置关闭），或 `Alt+T` 触发；气泡展示译文，支持替换/插入/复制
2. 三引擎均可在设置中配置与切换；自定义 AI 支持测试连接；明暗主题无视觉回归（截图归档）
3. 翻译请求经 Rust 代理发出：代理设置生效（可配置 override 验证）、apiKey 不出现在前端
4. 分段 id 对齐：AI 引擎漏翻/错位时报错重试，不静默展示错位结果
5. `cargo test`、`cargo fmt --check`、全套 Node 测试、Playwright e2e 全绿；`registry_command_id("translate.request")` 有锁定单测
6. Windows 产物增量 ≤ 200 KB
