# FEAT-005 翻译功能集成立项提案

- **日期**：2026-09-09
- **状态**：立项（待排期）
- **关联 backlog**：FEAT-005；与 FEAT-003（网络代理配置）协同
- **源码参考**：VastTranslator（LexiLayer）Chrome 插件 v0.10.9，位于 `D:\WorkDev\MyShare\VastTranslatorChromePlugin`

## 1. 背景

GlanceMD Ultra 用户（尤其读写双语文档的技术写作者）需要在编辑器内对选中文本快速翻译。VastTranslator 浏览器插件已沉淀了一套成熟的翻译引擎层（Google / Bing / 自定义 OpenAI 兼容 API + 分段对齐协议），本提案评估并规划将其核心能力集成进 GlanceMD Ultra。

## 2. 可行性结论

**可行，推荐实施。** 调研结论如下：

### 2.1 插件侧可移植资产

| 层 | 关键文件 | 可移植性 |
|---|---|---|
| 翻译引擎层（纯逻辑） | `src/background/openai-client.ts`（224 行）、`google-translate-client.ts`（40 行）、`bing-translate-client.ts`（34 行）、`translate-http.ts`、`retry.ts` | ✅ 高——仅用标准 `fetch`，无 Chrome API 依赖 |
| 协议层（纯逻辑） | `src/shared/messages.ts`（70 行）、`languages.ts` | ✅ 高——`TranslationRequest{segments:[{id,text}]}` → `TranslationResult[]`，AI 翻译用 JSON 结构化提示词 + id 对齐校验（防漏翻/错位） |
| 浏览器耦合层 | `src/content/*`（DOM 扫描/注入渲染）、`src/background/index.ts`、popup/options（React UI） | ❌ 不迁移——依赖 `chrome.*` API 与网页 DOM，与 GlanceMD 场景无关 |

需移植的核心代码约 **1000 行纯 TS**，改写为 GlanceMD 的 IIFE 纯 JS 模块后体量更小。

### 2.2 GlanceMD 侧承接条件

- 编辑器为纯 `<textarea>`（`index.html:170`），选区通过 `selectionStart/selectionEnd` 获取，远比插件的 DOM 选区逻辑简单
- 已有成熟浮层/面板模式可复用（`quick-open.js`、`search-panel.js`、`command-palette.js`）
- `settings.js` 已有设置面板，可挂翻译引擎配置
- **唯一硬约束——网络**：页面运行于自定义协议 `glancemd-ultra.localhost`，前端直接 `fetch` 外网受 CORS 限制（Google 公开接口不返回 CORS 头，自建 AI 端点亦未必放行）。**必须由 Rust 端做 HTTP 代理**：新增 IPC 消息 `translate_request`，Rust 转发请求并回传结果；顺带保证 API key 不出前端进程

## 3. 方案

### 3.1 MVP 范围（本提案交付目标）

1. **Rust 端**：新增 `ureq` 依赖（纯 Rust、体积小；不用 `reqwest`，太重）；IPC 新增 `translate_request`（入参：引擎配置 + segments；出参：results 或错误；移植 `translate-http.ts` 的超时/重试语义）
2. **前端新模块** `translate.js` + `translate.css`（IIFE 模式）：
   - 将 Google / Bing / OpenAI 三引擎的请求构造与响应解析移植为纯函数（输出请求描述，实际 HTTP 走 IPC）
   - 移植 `messages.ts` 分段协议与 id 对齐校验
3. **UI**：textarea 选中文本后出现浮动按钮 → 点击弹出翻译气泡，显示译文并提供「替换选区 / 插入到选区后 / 复制」操作；样式遵循紫→粉渐变设计语言（`--mk-heading` → `--mk-heading-end` 衍生 token）
4. **设置**：`settings.js` 新增「翻译」分节——引擎选择（默认 Google 免 key，开箱即用）、自定义 AI 引擎的 baseUrl / model / apiKey、目标语言；持久化到 localStorage（`glancemd-ultra-` 前缀）

### 3.2 明确不在本提案范围（后续增强）

- 全文对照翻译（preview.js 段落级双语渲染）
- 专家提示词体系（插件 `experts.ts` + 内置专家数据，可低成本后移）
- 翻译结果缓存
- SSE 流式输出（需 IPC 支持流式回传）
- 这些增强在 MVP 落地验证后另行立项。

### 3.3 体积与依赖评估

- `ureq` + `rustls` 预计增加 ≤ 1 MB，处于 2–8 MB 预算内（预算见 FEAT-004 背景）
- 前端保持零构建链、零 npm 依赖原则

## 4. 风险

| 风险 | 缓解 |
|---|---|
| Google 免 key 接口在国内网络下不可达 | 与 FEAT-003（代理配置）协同，Rust HTTP client 统一加载代理设置；设置页提供「测试连接」按钮 |
| AI 引擎响应错位/漏翻 | 移植插件的 id 对齐校验，校验失败即报错重试，不静默展示错位译文 |
| 跨仓库同步 | 不涉及——翻译为 Ultra 独有功能，无需 `[sync]` 到 GlanceMD |

## 5. 验收标准

1. 选中编辑器文本可一键翻译并在气泡中查看/替换/插入/复制
2. 三引擎（Google / Bing / 自定义 AI）均可在设置中配置并切换，测试连接可用
3. 无明暗主题视觉回归（双主题截图验证）
4. `cargo test`、`cargo fmt --check`、Playwright 冒烟套件全绿
5. Windows 产物增量 ≤ 1 MB
