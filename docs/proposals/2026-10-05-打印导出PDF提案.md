# FEAT-007 打印导出 PDF 立项提案

> 状态：已批准实施　|　提出日期：2026-10-05　|　来源：v0.9.0 用户反馈（pandoc 无引擎时 PDF 无路可走）

## 1. 背景与动机

FEAT-006 的 PDF 导出依赖外部引擎（xelatex / tectonic / typst），未装引擎的用户（如反馈人：本机只有 pandoc）无法出 PDF。经调查确认：

- **pandoc 本身不内置 PDF 引擎**，任何平台都需要外部排版器（思源笔记的 PDF 导出走其自渲染打印管线，与 pandoc pdf-engine 无关）
- **三平台系统打印栈均原生自带 PDF 输出**：Windows 内置 "Microsoft Print to PDF" 虚拟打印机；macOS 打印面板自带 "PDF → 存储为 PDF"；Linux GTK 打印对话框自带 "打印到文件"
- **wry 0.49 统一暴露 `WebView::print()`**（webview2/wkwebview/webkitgtk 三后端均有实现），一份代码三端弹原生打印对话框

因此新增**零依赖的打印导出路线**：把预览内容交给系统打印对话框，用户选择各平台自带的 PDF 输出。与 pandoc 引擎路线（排版级 PDF：目录、交叉引用、LaTeX 排版）**互补共存**——打印路线输出所见即所得的网页观感 PDF（mermaid 图表可直接打印，这是引擎路线做不到的）。

## 2. 方案要点

1. **入口**：导出菜单 PDF 项拆为两项——「导出为 PDF（打印）」始终可用；「导出为 PDF（排版引擎）」保持引擎检测驱动（未检测到禁用 + 原因）。命令面板同步拆分：`export.pdf.print`（新）与 `export.pdf`（保留，语义不变）。
2. **打印流程**：点击后 ① 校验有文档 → ② 将 html 主题切为浅色并**强制刷新预览 DOM**（纯编辑模式下预览是陈旧的：`marked.parse` + `resolveLocalImages` + `renderMermaidCharts` 三连）→ ③ 上行 `app.print` → Rust `webview.print()` 弹系统对话框。
3. **打印样式** `print.css`（`@media print`）：只保留 `body > #content > #editor-column > #preview-container` 链（其余全部 `display:none`），预览容器脱离应用内滚动/定位完整铺开；`[data-theme]` 上以同特异性后序覆盖 `--mk-*` token 为浅色纸张配色（兜底，正常路径已由②的浅色渲染覆盖）；`@page` 页边距 + 分页规则（标题不孤行、pre/blockquote/table/mermaid 不跨页截断、代码自动换行）。
4. **静默导出（不弹对话框一键存 PDF）不做**：三平台 API 互不相同（WebView2 PrintToPdf / WKWebView createPDF / WebKitGTK 打印设置），wry 0.49 未暴露，属 v2 增强。
5. **主题行为**：打印渲染会把主题切到浅色并保持（打印对话框关闭时机三平台不一致，无法可靠恢复；用户点主题按钮即切回）。暗色 mermaid 图在浅色纸张上不可读，浅色渲染是刻意行为。

## 4. 验收标准

1. 无引擎机器上「导出为 PDF（打印）」可用且能出 PDF；「导出为 PDF（排版引擎）」禁用并说明原因
2. 打印内容为**当前编辑器 buffer** 的最新渲染（含未保存修改），纯编辑模式下打印不出现陈旧预览
3. 打印页只有预览内容：无标题栏/标签栏/侧栏/编辑器/状态栏；暗色主题下打印为浅色纸张配色；mermaid/代码块不跨页截断
4. `app.print` IPC 链路有测试覆盖；`node --test` / Playwright / cargo 全绿；明暗双主题截图
