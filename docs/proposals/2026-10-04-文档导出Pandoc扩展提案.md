# FEAT-006 文档导出（Pandoc）扩展立项提案

> 状态：待评审　|　提出日期：2026-10-04　|　决策确认：2026-10-04（用户已拍板，见 §2）

## 1. 背景

用户需要把 Markdown 文档交付为 Word / EPUB / PDF 等格式。项目定位是"轻量原生工作区编辑器"（二进制预算 2–8MB，见 backlog FEAT-004），不可能内置文档转换引擎。Pandoc 是事实标准的三平台转换工具（Windows / macOS / Linux 均有官方发行版，当前稳定版 3.7.0.2），采用**"功能内置、二进制外置"**模式：应用内置导出能力，检测并调用用户机器上的 pandoc，检测不到时提供安装指引——与语层翻译（FEAT-005，"内置扩展 + 外置翻译引擎 API"）同一模式，只是调用对象从网络 API 换成本地二进制。

本功能依赖工作区文件上下文，属 Ultra 特有，**不进共享内核，无 `[sync]`**。

## 2. 已确认决策（2026-10-04 用户拍板）

| # | 决策 |
|---|---|
| D1 | **范围**：v1 只导当前文件；批量/整文件夹导出放 v2 |
| D2 | **PDF**：v1 即支持，由 PDF 引擎检测驱动（未检测到引擎时禁用该项并提示原因） |
| D3 | **对外文案**：入口叫「导出」，**不出现 Pandoc 字样**；二级菜单按导出类型分项。Pandoc 仅出现在设置页（后端配置处） |
| D4 | **入口**：顶栏语层翻译图标旁新增「导出」功能图标 |
| D5 | **免重启**：Windows 下刚装完 pandoc 不重启应用即可用——检测不得只依赖进程环境变量中的 PATH 快照，必须支持绝对路径兜底探测与自定义路径即时生效 |
| D6 | **设置页**：提供当前平台对应的**指定版本** pandoc 官方安装包下载直链，用户点击下载、安装后完成配置即可使用 |

## 3. 可行性结论

- **体积零增长**：`std::process::Command` 已在用（`open_external`），无新 crate；前端新增 js/css 约 10KB（gzip 后 ~3KB），预算内
- **架构全部有先例**：异步 IPC 照搬 `translate.request` 事件回执模式；`ipc.rs` 前缀白名单补 `pandoc.`（BUG-001 教训）；另存为对话框复用 `file_ops::pick_save_file`；外链打开复用 `open_external`（http/https 校验既有）；进程安全纪律沿用 `CREATE_NO_WINDOW` + 参数数组（绝不拼 shell 字符串）
- **跨平台**：pandoc 三平台官方发行；`pandoc --version` 探测三平台同一套代码。唯一平台差异是 **macOS/Linux GUI 启动不继承 shell PATH**（launchd 桌面环境 PATH 极简，Homebrew 的 `/opt/homebrew/bin` 探测不到）——由 §4 兜底路径清单解决，这也是 D5 的同源问题
- **免重启可行**（D5）：兜底探测是**绝对路径** spawn，完全不依赖 PATH 环境变量；MSI / pkg / apt 装完后落在固定位置，下一次打开导出菜单（按需探测）即可发现；自定义路径保存即校验生效

## 4. 架构方案

### 4.1 Rust 模块 `src/pandoc.rs`（新建）

```
detect(path_hint: Option<&str>) -> DetectResult
  DetectResult { found, version, source }   // source: hint | path | fallback
export(request) -> 异步事件回执
  request  { request_id, format, out_path, source_dir, markdown }
  回执      { request_id, ok, out_path?, stderr 摘要?, elapsed_ms }
```

**检测三层**（按序尝试，命中即返回版本号）：

1. **自定义路径**（设置 `pandoc.path`，非空时最高优先）：直接 spawn `<该路径> --version`，失败不回退、直接报错（用户明确指定了就该报错，避免静默用错二进制）
2. **PATH**：spawn `pandoc --version`
3. **兜底绝对路径清单**（不受 PATH 快照影响，覆盖 D5）：
   - Windows：`C:\Program Files\Pandoc\pandoc.exe`、`%LOCALAPPDATA%\Pandoc\pandoc.exe`
   - macOS：`/opt/homebrew/bin/pandoc`、`/usr/local/bin/pandoc`
   - Linux：`/usr/bin/pandoc`、`/usr/local/bin/pandoc`、`~/.local/bin/pandoc`

**PDF 引擎检测**：pandoc 已找到时，依次 spawn `xelatex --version`、`tectonic --version`、`typst --version`（同样走 PATH + 兜底），返回可用引擎列表与优先序。检测结果带短时缓存 + 显式「重新检测」按钮，**不缓存"未找到"为永久状态**。

**导出**：`Command::new(pandoc_path).args(模板参数)`，markdown buffer 经 **stdin** 写入（未保存改动可导，不落临时文件、不触发监听/冲突保护），`--resource-path=<源文件目录>` 解析相对图片；超时 120s 强杀；stderr 截断回传。

### 4.2 IPC

新增 `pandoc.detect`（同步回包，探测很快）与 `pandoc.export`（异步：线程 + `evaluate_script` 事件回执，照搬 `translate.request` 模式，requestId 关联）。`ipc.rs` 前缀白名单补 `pandoc.`。另加 `file.pickPandoc`（设置页「浏览…」触发，返回所选文件路径，复用既有文件对话框模式）。

### 4.3 前端 `src/frontend/export.js` + `export.css`（新建，IIFE）

**入口一：顶栏图标**（D4）。`index.html` 的 `#btn-translate` 之后新增 `#btn-export`（下载/导出托盘 SVG，复用 titlebar 按钮样式与 `data-i18n-title` 机制）。点击打开下拉菜单（复用 help-menu 的下拉样式与 `--tree-menu-*` token）：

```
#btn-export → 下拉：
├─ 导出为 Word 文档        .docx
├─ 导出为 EPUB 电子书      .epub
├─ 导出为 HTML             .html
├─ 导出为 PDF              .pdf（未检测到引擎时禁用 + 原因 tooltip）
├─ 导出为 ODT 文档         .odt
├─ ────────────────
└─ 导出设置…               （打开设置·导出分类）
```

菜单顶部有状态行：pandoc 版本（如 `pandoc 3.7.0.2`）或「未检测到 pandoc」+「查看安装指引」按钮。未检测到时五个导出项全部禁用。

**导出流程**：点格式项 → `pick_save_file`（按格式带扩展名过滤器）→ 按钮进入导出中态（spinner）→ 成功 toast「已导出到 <路径>」（附「打开所在文件夹」操作，复用 `open_external` 的文件夹变体或新增 `file.reveal` 命令）→ 失败 toast 展示 stderr 摘要（PDF 失败附 CJK 字体提示链接）。

**入口二：☰ 应用菜单**（D3）：`help-menu.js` MENU_DEFS 的「扩展」children 追加 `{ commandId: 'export.menu', labelKey: 'help.menu.export' }`（导出…），打开与顶栏相同的下拉。

**入口三：命令面板**：`export.menu` + 五个格式命令 `export.docx/epub/html/pdf/odt`（含 `commandDesc.export.*`），同 `command.translate.*` 模式。

**默认键位**：`Ctrl+Shift+E`（macOS `Cmd+Shift+E`）绑定 `export.menu`。已核对 `default-keybindings.js`，E 组键位空闲。其余格式命令不设默认键。

### 4.4 设置页「导出」分类

`settings.js` CATEGORIES 在翻译分类后新增 `export` 分类：

- **状态行**：`pandoc 3.7.0.2（来源：PATH / 内置路径 / 自定义路径）` 或 `未检测到`；「重新检测」按钮
- **自定义路径**（覆盖"电脑上已装但不被自动探测到"的场景，含**便携版** zip 解压用户）：文本输入 + 「浏览…」按钮（原生文件选择器：`file_ops` 新增 `pick_pandoc_binary()`，复用既有 `rfd` 依赖；Windows 过滤 `.exe`，macOS/Linux 不过滤——pandoc 二进制无扩展名）+ 保存动作。保存或选择后立即 spawn `<路径> --version` 校验并回显版本号；失败红字提示（路径不存在 / 无法执行），**全程无需重启**（D5）。路径设置后检测固定使用该二进制、不回退其他来源（用户明确指定了就该报错，避免静默用错）
- **下载直链**（D6）：按 `document.body.dataset.platform` 显示当前平台对应的**指定版本**安装包直链，点击走 `open_external`：

| 平台 | 直链（版本常量 3.7.0.2） |
|---|---|
| Windows x64 | `https://github.com/jgm/pandoc/releases/download/3.7.0.2/pandoc-3.7.0.2-windows-x86_64.msi` |
| macOS Apple Silicon | `https://github.com/jgm/pandoc/releases/download/3.7.0.2/pandoc-3.7.0.2-arm64-macOS.pkg` |
| macOS Intel | `https://github.com/jgm/pandoc/releases/download/3.7.0.2/pandoc-3.7.0.2-x86_64-macOS.pkg` |
| Linux | `https://github.com/jgm/pandoc/releases/download/3.7.0.2/pandoc-3.7.0.2-1-amd64.deb`（deb 资产带 `-1` 打包修订号） |

  另附「全部平台 / 其他格式」链接到 Release 页。版本与链接模板收敛为前端一处常量，升级只改一处。分类说明文案注明安装后无需重启、点「重新检测」或直接重开导出菜单即可。

### 4.5 i18n

`i18n.js` zh/en 新增：`toolbar.export`、`export.*`（菜单项/状态/指引/toast）、`command.export.*` + `commandDesc.export.*`、`help.menu.export`、`settings.exportCategory` + Desc、`settings.pandoc.*`。清理失效词条照常走 i18n 测试约束。

## 5. 导出格式与参数模板

| 格式 | 目标参数 | 说明 |
|---|---|---|
| Word | `-f markdown -t docx -o <out>` | |
| EPUB | `-f markdown -t epub3 -o <out>` | 显式 epub3 |
| HTML | `-f markdown -t html5 --standalone --embed-resources -o <out>` | 单文件可分享；`--embed-resources` 需 pandoc ≥ 2.19，检测已取得版本号，旧版回退 `--self-contained` |
| ODT | `-f markdown -t odt -o <out>` | |
| PDF | `-f markdown -o <out> --pdf-engine=<检测到的引擎>` | 引擎优先序 xelatex > tectonic > typst；未检测到则该项禁用 |

所有模板均附加 `--resource-path=<源文件目录>`（未保存新文件时用工作区根目录）。v1 不开放用户自定义参数，格式对应固定模板，攻击面为零；元数据标题取自文件名。

## 8. 风险

| 风险 | 应对 |
|---|---|
| pandoc 2.x/3.x 参数差异 | 保守参数集 + 版本判定（HTML 嵌入资源标志按版本选择）；状态行展示版本号便于诊断 |
| 中文 PDF 需 CJK 字体/引擎配置 | 不做静默兜底，失败时透传 stderr 并给提示链接（设置页 FAQ 说明推荐 tectonic 或 xelatex + 字体） |
| macOS/Linux GUI 环境缺 PATH | 兜底绝对路径清单（§4.1），这正是 D5 免重启设计的一部分 |
| 大文档/慢盘导出超时 | 120s 超时强杀 + 明确报错；v1 不做取消按钮（超时即终态） |
| 下载直链随 pandoc 升级失效 | 版本常量收敛一处，随验证节奏手动升级；同时常驻 Release 页链接兜底 |
| open_external 现为 URL 白名单 | 下载直链为 https GitHub 域，既有 http/https 校验直接放行；「打开所在文件夹」如新增 `file.reveal` 需同步路径白名单纪律（拒绝引号/空白字符的既有检查沿用） |

## 9. 验收标准

1. 已装 pandoc（PATH / 兜底路径 / 自定义路径任一来源）：顶栏导出菜单显示版本号，五格式中可用的均可导出成功，产物能被对应应用正常打开
2. 未装 pandoc：导出项禁用、指引按钮可达设置·导出分类，下载直链按平台正确显示且能打开
3. **免重启验收（D5）**：应用运行中安装 pandoc（或填入自定义路径保存 / 经「浏览…」选择便携版 pandoc 二进制保存），不重启，重新打开导出菜单/点重新检测后立即可导；自定义路径指向无效文件时保存给出明确报错且不静默回退
4. 未保存的修改能被导出（stdin 路径生效）；相对路径图片在 HTML 导出中正确解析（resource-path 生效）
5. PDF 在无引擎机器上禁用并显示原因，有引擎机器上正常出 PDF
6. `cargo test` / `cargo fmt --check` / `node --test` 全量 / Playwright 冒烟全绿；导出菜单与设置·导出分类提供明暗双主题截图
7. 三平台编译通过（CI Build workflow 四平台绿）；macOS/Linux 的真实导出矩阵在阶段 7 平台验证中覆盖
