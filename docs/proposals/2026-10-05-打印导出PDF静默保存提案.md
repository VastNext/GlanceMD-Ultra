# FEAT-008 打印导出 PDF 静默保存（Windows PrintToPdf）立项提案

> 状态：已批准实施　|　提出日期：2026-10-05　|　来源：FEAT-007 用户反馈

## 1. 背景

FEAT-007 的「导出为 PDF（打印）」在 Windows 上弹 WebView2 系统打印对话框，用户反馈两点：
1. 打印机需手动切换为 "Microsoft Print to PDF"，选不对就没有保存入口；
2. 保存文件名不是 md 文件名。

**技术约束**：wry 0.49 的 `print()` 无参数，WebView2 的 `ShowPrintUI` 没有预选打印机/预填文件名的 API——对话框路线在 Windows 上无法满足这两点。正解是 **WebView2 `PrintToPdf` 静默导出**：应用自己弹"另存为"对话框（PDF 过滤器 + 预填 md 文件名），选定路径后由 WebView2 直接生成 PDF（应用 `@media print` 样式，即 print.css），全程无打印机选择。

## 2. 方案要点

1. **Windows**（本次范围）：`app.printToPdf` IPC → 另存为对话框（`file_ops::pick_export_file("pdf", suggest_name)`，文件名 = md 文件名.pdf）→ `WebViewExtWindows::controller()` 取 `ICoreWebView2Controller` → `CoreWebView2` cast `ICoreWebView2_16` → `PrintToPdf(路径, None, handler)`；`wait_with_pump` 消息泵保活等待完成（UI 不卡死），结果同步回执前端 toast。零新增依赖（webview2-com 0.35 已是直接依赖，自带闭包式 `PrintToPdfCompletedHandler`）。
2. **默认设置（None）**：默认纸型与页边距；背景打印（ShouldPrintBackgrounds）需要 environment 创建 ICoreWebView2PrintSettings，wry 0.49 未暴露 environment，v1 不开（代码块无底色但有边框，可读）。
3. **macOS / Linux 不变**：仍走 `app.print` 系统打印对话框（macOS 的 PDF 按钮、GTK 的打印到文件入口醒目易用）。静默导出的 macOS（NSPrintOperation 预设/`createPDF`）与 Linux（webkit2gtk 编程式打印设置）路线留后续。
4. **前端**：Windows 走 `app.printToPdf`（toast「正在导出 PDF」→ 结果回执 `workspace:print-pdf-result`，成功记入「上次导出」支持打开所在文件夹）；其他平台维持 `app.print`。
5. **菜单文案**：打印路线更名「导出为 PDF（打印样式）」（不再弹打印对话框）；引擎路线「导出为 PDF（排版引擎）」不变。

## 3. 验收标准

1. Windows 上点击「导出为 PDF（打印样式）」→ 另存为对话框预填 md 文件名（.pdf 扩展名）→ 保存后 PDF 直接写出，无打印机选择步骤
2. 产物应用 print.css（仅预览内容、浅色纸张、分页规则）
3. 取消另存为 → 静默复位无报错；失败 toast 透传原因
4. macOS/Linux 行为与 v0.10.1 一致（系统打印对话框）
5. 测试：export.test.js 平台分支断言（Windows → app.printToPdf + suggestName；其他 → app.print）；verify-export-pandoc 断言 IPC；node/cargo/Playwright 全绿
