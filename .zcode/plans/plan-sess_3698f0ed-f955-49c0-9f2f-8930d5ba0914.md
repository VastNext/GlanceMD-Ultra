## 根因速查（已探明）

| # | 问题 | 根因 |
|---|---|---|
| 1 | 关闭按钮关不掉 | `settings.css:20` `display:flex` 覆盖了 UA 的 `[hidden]{display:none}`，`hidden=true` 后面板仍可见 |
| 2 | 不居中/不可拖/不可调 | CSS 只有 `left:50%+transform` 定位；JS 无拖动/缩放逻辑 |
| 3 | 侧栏字小 | 树 13px、Outline 13px 硬编码，无用户设置 |
| 4 | 打开设置JSON=打开我的电脑 | `commands.rs:518` 无条件 reveal 不存在的文件；`explorer /select` 找不到目标就只开窗口 |
| 5 | 搜"主题"无匹配 | 搜索只过滤**当前分类**；且旧构建只匹配英文 key（新版已含中文） |
| 6 | 无国际化 | 无 i18n 基础设施，字符串散布各模块（中英混排） |
| 7 | 快捷键只有 `{}` | keybindings 分类走通用渲染（overrides 是 object→JSON 文本框）；与实际生效的 `window.Keybindings`（localStorage）零交互、无默认键表展示 |
| 8 | 编辑器设置不生效 | 除主题外**没有任何应用逻辑**：fontSize/tabSize/wordWrap 硬编码在 CSS/editor.js；lineNumbers 的行号 UI 根本不存在 |
| 9 | 监听无开关 | schema 的 `watching` 类只有 autoSave 两字段，无启停布尔；Rust 已有 `watcher.pause/resume` 命令可复用 |
| 10 | dark 下下拉框白边 | 全仓缺 `color-scheme` 声明——白色是**原生下拉弹层**（UA 默认浅色），select 边框本身是深色 |
| 11 | 写用户目录 | `settings_base()`= `%APPDATA%\glancemd-ultra`（settings.json、recovery\）；`window_state.rs` 同目录；WebView2 UDF 默认 exe 旁 |

## 实施（三波，按依赖排序）

### Wave 1（三条并行流，文件不重叠）

**流 A：设置页 UX 快修**（worktree `settings-ux-fixes`）
- [1] `settings.css` 加 `.settings-panel[hidden]{display:none}`
- [2] 面板可拖动（按住 header 拖移，首次拖动把 `left:50%+transform` 换成绝对 left/top）+ 可调大小（右下角 resize 手柄或 CSS `resize:both`，min/max 约束），尺寸/位置持久化到 localStorage
- [5] 搜索改**全局**：有关键词时跨七类聚合匹配（按分类分组展示，点击跳分类），无关键词恢复当前分类视图
- [10] `style.css` 加 `color-scheme`（dark:root 与 light 各自声明）+ select/option 主题化兜底样式
- [4] Rust `settings_open`：文件不存在时先写入默认 Settings 再 reveal（`commands.rs`）
- 测试：hidden 关闭、全局搜索、settings_open 创建文件（Rust 探针）

**流 B：编辑器设置接线 + 监听开关 + 侧栏字号设置**（worktree `settings-apply`，含 Rust schema）
- [8] 新模块 `src/frontend/settings-apply.js`：订阅 `workspace:settings-effective` 并提供 `apply(effective)`——fontSize（CSS 变量 `--editor-font-size`，替换硬编码 13.5px）、tabSize（CSS `tab-size` + editor.js Tab 插入空格数）、wordWrap（textarea wrap/white-space 切换）、largeFileMB 与 search maxResults/maxFileSizeMB（注入 `workspace.search.start` 的 options 默认值）；启动时（commands.js 初始化处）主动请求一次 get-effective 使设置在开机即生效
- **行号**：实现编辑器行号槽（`#editor-gutter`，数字列与 textarea 滚动同步），`editor.lineNumbers` 控制显隐——这是本波最重的一块
- [9] Rust schema `watching` 加 `enableWatcher: bool = true`（serde default，v1 加字段无需迁移）+ 前端 switch；变更时调 `watcher.pause/resume`；`workspace.open` 启动 watcher 前检查该设置
- [3] Rust schema `appearance` 加 `sidebarFontSize: u32 = 14`；前端应用到 CSS 变量 `--panel-font-size`（树行/Outline/面板标题改用该变量），默认即用户要的"调大一号"
- 测试：Rust schema 探针、settings-apply 单测

**流 E：便携数据目录**（worktree `portable-data-dir`，Rust only）
- [11] `commands.rs` 新增 `data_base()`：优先 `exe目录/data/`，**写入探测**（create_dir + 写探针文件）失败则回退 `dirs::config_dir()/glancemd-ultra`；`settings_base()`、`recovery_store()`、`window_state::config_path()` 全部改走该函数；WebView2 UDF 设 `WEBVIEW2_USER_DATA_FOLDER` 指向 `data_base()/webview2`（main.rs 在创建 webview 前设置）
- macOS 上 `.app/Contents/MacOS` 探测几乎必然失败→自动回退用户目录，即满足"有权限问题就放弃（该平台回退）"；Windows/Linux（含 AppImage 目录）通常可写，获得便携行为
- 单元测试：探测回退逻辑（注入路径）

### Wave 2

**流 C：快捷键设置 UI**（worktree `keybindings-editor`，等 Wave 1 合并后开工，避免 settings.js 冲突）
- [7] settings.js 快捷键分类重写：从 `window.Keybindings.defaults + effective()` 渲染**全部命令行**（命令中文名 + 当前组合键 + 录制按钮），点录制进入捕获（Esc 取消、Backspace 清除、冲突时红字阻止保存——复用 `Keybindings.save/conflict`），每行可单独恢复默认，另有"全部恢复默认"
- 持久化维持现有 localStorage 机制（`Keybindings.save` 已带冲突检测），schema 的 `keybindings.overrides` 本轮不动（契约文档标注保留）
- 测试：渲染行数、录制→保存、冲突阻止、恢复默认

### Wave 3

**流 D：国际化**（worktree `i18n`，最后进行——要在全部 UI 改动定稿后迁移字符串）
- 新模块 `src/frontend/i18n.js`：字典 `zh-CN`（默认，迁自现有文案）+ `en`；`I18n.t(key, params?)`、`I18n.setLanguage(lang)`、`I18n.getLanguage()`
- Rust schema `appearance` 加 `language: String = "zh-CN"`（serde string，便于未来加语言不必改枚举）；`settings-apply.js` 应用时设置 I18n 语言并广播 `language-changed`，各模块重渲染动态文案
- 字符串迁移范围（以探索清单为准）：settings.js、tabs.js（含右键菜单/确认）、project-tree.js（菜单/确认/aria）、recovery.js、search-panel.js、quick-open.js、command-palette.js、commands.js 命令 label、app.js（Saved/Recent/confirm 等）、index.html 工具提示与占位符、outline.js；Rust 侧对话框与错误文案（main.rs 关闭确认、file_ops 选择器标题、commands.rs/ipc.rs 错误）改为经前端事件取文案或保留中文并登记为已知边界——**方案：Rust 错误信息保持现状（多为调试语义），前端对 `error` 事件做关键值映射翻译**，避免 Rust 侧 i18n 框架
- settings 外观分类加"界面语言"下拉（zh-CN 简体中文 / en English），切换即时生效
- 测试：i18n 模块单测（默认语言、切换、缺键回退）+ 各模块渲染语言断言（抽核心）

## 风险与边界

- 行号槽是 textarea 之上的覆盖层，需处理滚动同步与 wordWrap 换行导致的行号漂移——wrap 开启时行号按"软行"计有已知偏差，实现时按"逻辑行"编号并在契约中注明（与 VS Code 行为一致需 wrap-off 配合，文档写明）
- i18n 字符量大（约 120+ 条），采用两份扁平字典 + 缺键回退 zh-CN；Rust 侧原生对话框文本本轮保持中文，登记为边界
- 便携目录在 Program Files 等受保护位置会探测失败→自动回退用户目录，行为符合"有权限问题就放弃"
